01The specification

SQL is the retrieval interface.
Evidence is the contract.

The three supplied essays argue for agents that query structured context through SQL. They are architectural commentary, not a published protocol. This repository turns that idea into a concrete specification for Colors Context Skills.

The local Context Skill Standard supplies the admission rules. A Context Skill records knowledge from a verified build and must carry symptom routing, provenance, pinned versions, a failure catalogue, and support-style evals. A searchable document alone does not satisfy that contract.

01 / CAPTUREOriginal files

Download selected skills with pinned npx skills. Verify every path and byte against the upstream commit.

02 / INDEXPostgreSQL

Store revisions, documents, passages, and artifact classifications.

03 / RETRIEVEBounded SQL

Search symptoms, inspect candidate passages, then fetch the cited source.

04 / ASSEMBLEAgent context

Include relevant evidence and version limits within a context budget.

Give the agent a schema description, documented query examples, and a controlled SQL interface. Keep catalog access read-only; grant separate, owner-scoped writes to working memory. It should discover relevant skills before it loads long documents. It must cite a revision and source location when it uses a claim.

"Manage context" means selecting which database records enter the next prompt. The database stores persistent knowledge; the agent still has a finite prompt window. A retrieval query does not alter that window until the tool returns its results.

Required behavior

  • Acquire skills with a pinned npx skills invocation at an identified upstream commit. Reject missing, changed, extra, or unsafe files.
  • Store the complete payload verbatim in PostgreSQL with relative paths, hashes, and acquisition provenance. Retrieval must work after temporary staging is removed.
  • Separate generic procedures, Context Skills, and Package Skills. Never infer verified status from a folder name.
  • Scope retrieval to a chosen revision. A pin change makes affected claims unknown until re-verification.
  • Return small discovery results first, then expand selected passages. Report truncation instead of silently dropping evidence.
  • Keep knowledge import, agent retrieval, and permission to execute a procedure separate.
02The data model

Normalize the things you join.
Keep the text you need to prove.

A single JSONB document per skill preserves flexibility but makes revisions and citations difficult to enforce. Splitting every sentence into a claim loses the author's conditions and encourages invented structure. Use a relational core with lossless source documents and bounded passages.

Use JSONB for literal pin cells, eval assertions, and original eval fixture objects. Use typed columns and foreign keys for identities, revision membership, hashes, and source locations. Avoid an entity-attribute-value model for fields the agent regularly filters.

Choose lexical search first

Failure reports often include exact error strings. PostgreSQL full-text search supports word-based discovery with a GIN index. Literal substring queries retain punctuation-sensitive matches. An embedding index can be added after retrieval evals show a gap, but it should not replace exact error matching or version filters.

A revision is more than a Git commit

Record the source commit and a hash of the captured content. Retain source bytes independently of later edits. The importer downloads selected skills through npx --yes skills@1.6.0 add in an isolated temporary project. An independent Git fetch verifies the complete inventory and exact bytes against the specified commit. Missing or changed installer output fails verification; Git objects never fill gaps. The database retains every file, including scripts and binary assets, after staging is removed. Remote citations identify the verified source commit. Identical content retains its version identity, while each acquisition records its own provenance.

The corpus's pinned software versions belong to the evidence. They are different from the Git revision that contains the skill. Neither an acquisition timestamp nor a recent commit proves that the underlying deployment was re-tested. The --check command verifies a fresh download without replacing historical acquisition metadata.

The SQL migration defines the constraints, immutability triggers, indexes, and current-revision views. The specification describes the retrieval and ingestion contracts.

03The query loop

Discover. Inspect. Cite.

Start with the symptom in the user's report. Ask SQL for a short list of candidate passages, inspect their version conditions, and fetch the exact source before proposing a fix.

POSTGRESQL / EXAMPLE

This is a local query explorer. It displays examples and does not connect your browser to a database.

Control the result size at the tool boundary

A query's LIMIT is useful but insufficient. A single row can hold a long document. The local runner caps rows and serialized JSON bytes, enforces a five-second SQL timeout and an external deadline, and reports truncation with continuation fields. Its fixed parameterized operations preserve citations when returning text slices.

CSV can reduce repeated field names in tabular results. Use proper quoting for commas, line breaks, and quotes, and benchmark token usage with the actual corpus. The essays' claimed savings are not a guarantee for this implementation.

Reconstruct task memory after a restart

Store observations, hypotheses, decisions, pending tasks, tool results, and summaries in working.item. Each item belongs to an expiring run and may cite an exact catalog section through a foreign key. Retrieve active items by priority under a byte budget. Byte limits are not token limits; a model-aware runner still needs to count tokens.

The sql-context skill saves decisions and open work, then restores them in a later session using the same portable project ID and task key. The local checkout path is separate metadata, so moving the checkout does not change task identity within the same database login. It can mark notes done or superseded. Automatic summarization, model-context compaction, and expiry scheduling remain agent-service work. Summaries should preserve citations and unresolved uncertainty.

Do not turn a search hit into a command

The refresh-oci-token entry describes an authentication procedure. Retrieving it does not authorize running its script, opening a login session, or changing credentials. Source text is evidence for the agent to assess, not a trusted instruction channel.

05Access and correctness

A read-only query still needs limits.

Use a dedicated database login that can select approved catalog relations and cannot mutate them. Give it explicit working-memory writes only if the task requires them. Keep the importer on a separate credential. A read replica can reduce workload impact, but it does not fix excessive grants, expensive queries, or tenant isolation.

Enforce in PostgreSQL

  • Grant only required schema usage and relation access. Deny ownership, superuser privileges, and BYPASSRLS.
  • Restrict function execution and schema creation. A query beginning with SELECT is not a security policy.
  • Use statement, lock, and idle-transaction timeouts as operational defaults.
  • The reference working-memory tables force row policies based on session_user. Use different logins for different owners and test with the actual agent role.

Enforce in the service

  • Authenticate callers before assigning database access.
  • Bound query duration, concurrent work, row count, and result bytes.
  • Record query outcomes and timing without copying secrets into public logs.
  • Treat returned documents as untrusted content. Require separate authorization for actions they describe.

A client-set variable such as app.current_tenant_id is not a secure identity by itself. If arbitrary SQL can change the variable, a scoped view can expose another tenant. Bind identity outside agent control, use correctly enforced row policies, or isolate tenants with separate credentials or databases.

A shared connection-pool login identifies the pool, not the human using it. The reference policy does not separate users behind that shared login. Production pooling must preserve a trusted identity boundary.

Keep review and recall separate

Importing a file proves that the importer captured that file. A source author may report a live verification; the database should preserve that statement without claiming it repeated the test. Automatically extracted claims need review before admission as verified facts.

When dependencies change, compare the new pin set, mark affected assertions for re-verification, and run the skill's evals and retest instructions. Record the new evidence in a new revision. Keep historical revisions available for users on older versions.

06Implementation scope

A reproducible starting point.

This repository contains a persistent local PostgreSQL service, the sql-context agent skill and bounded SQL helper, source acquisition tooling, validation, and this standalone page. The source corpus remains traceable to its recorded revision and document paths.

Acceptance before wider use

Acquire the same commit again and confirm content versions stay stable. Reject missing files, changed bytes, extra files, and unsafe paths before replacing output. Remove staging, recover the complete payload from SQL, and compare hashes. Search exact error strings, then paraphrased symptoms. Check that every returned passage resolves to the captured source. Test rejected writes, query cancellation, truncation, and cross-tenant denial before granting production access.

Compare this SQL path with the existing skill-loading workflow using the same support prompts. Measure correct routing, correct diagnosis, citation accuracy, stale-version mistakes, bytes returned, and tool calls. Keep SQL because the measured workflow works better, not because the essays claim it always wins.
